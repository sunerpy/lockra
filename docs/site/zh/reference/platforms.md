# 平台说明

本页列出 Windows、macOS、Linux 和 Android 应用之间的差异。

## Windows

- **版本**：Windows 10 和 11，x64 与 ARM64。Lockra 使用 Microsoft Edge WebView2，这两个版本的系统都已自带；缺少时，安装程序会自动下载。
- **安装**：按用户安装，不需要管理员权限。安装程序目前尚未签名，因此首次启动前 SmartScreen 会请你确认。
- **在本机记住**使用凭据管理器。
- **剪贴板**：复制的验证码不会进入剪贴板历史（`Win V`）、云剪贴板，也不会被剪贴板监视程序读取。
- **截屏**：显示密钥或导出二维码期间，窗口无法被截取。
- **窗口**：Lockra 自行绘制标题栏，因此鼠标悬停在最大化按钮上时不会出现贴靠布局；`Win ←` 和 `Win →` 仍可贴靠窗口。

## macOS

- **版本**：macOS 11 及以上，适用于 Apple 芯片和 Intel 的 dmg 各一个。
- **首次启动**：应用目前尚未使用 Apple Developer ID 签名；请在「系统设置 › 隐私与安全性」中选择「仍要打开」。
- **在本机记住**使用钥匙串；应用内更新后无需再次允许（见下文）。
- **剪贴板**：复制的验证码会被标记为不进入剪贴板历史。
- **截屏**：显示密钥或导出二维码期间，窗口无法被截取。

### 更新后不再询问钥匙串

<StatusTag status="available" /> 自 0.7.1 版起提供。

Mac 版改为使用 Lockra 固定的签名证书，应用内更新在安装新版本之前，会把本机记住的密钥交给新版本保存。更新并重新打开后，macOS 不再询问是否允许 Lockra 使用钥匙串，Touch ID 照常解锁。从 0.7.0 或更早的版本升级到 0.7.1 的那一次，以及手动安装 dmg 之后，macOS 仍会询问一次。

### 新版本无法接管密钥时

<StatusTag status="building" />

如果新版本无法接管本机记住的密钥，更新不会安装。Lockra 继续运行当前版本，提示「新版本无法接管钥匙串中的设备密钥，未安装更新」，并把原因写入 `~/Library/Logs/dev.lockra.desktop/lockra.log`。0.7.4 及更早的版本遇到这种情况仍会安装更新，重新打开后 macOS 会询问一次。

## Linux

- **安装包**：.deb、.rpm 和 AppImage，适用于 x64 与 ARM64。Lockra 需要 WebKitGTK 4.1；X11 和 Wayland 均可使用。
- **在本机记住**需要支持 Secret Service 的钥匙串，例如 GNOME 钥匙圈或 KWallet。没有这类钥匙串的桌面上，这项设置不可用，并会说明原因。
- **剪贴板**：复制的验证码会被标记为不进入剪贴板历史；KDE 的剪贴板会遵守这个标记，其他剪贴板管理器不一定遵守。
- **截屏**无法阻止：Linux 没有提供让应用把窗口排除在截取之外的方法。显示密钥和导出的页面会说明这一点；这些页面打开期间，请注意屏幕共享。

## Android

<StatusTag status="available" /> 自 0.7.0 版起提供。

- **版本**：Android 8 及以上的 ARM64 手机，使用发布页上的 APK 安装。
- **解锁**：使用主密码，或「设置 › 安全 › 使用指纹解锁」，后者把保险库的密钥保存在手机的安全硬件中。手机上没有不经指纹验证的「在本机记住」。之后录入新的指纹会使这个密钥失效，在重新开启这项设置之前需要使用主密码解锁。
- **离开应用**（切换到其他应用、回到主屏幕或关闭屏幕）时，保险库会立即锁定。
- **截屏**：Lockra 的界面始终无法被截屏或录屏，最近任务中也只显示空白卡片。
- **剪贴板**：复制的验证码会被标记为敏感内容，输入法的剪贴板历史和粘贴预览不会显示它。
- **备份**：保存和恢复都通过系统的文件选择器，手机上没有自动备份。Android 自带的备份和设备迁移不包含 Lockra，因此请保留 Lockra 备份。
- **更新**：「设置 › 关于 › 检查更新」；有新版本时会打开该版本的发布页。
