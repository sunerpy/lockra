# 浏览器扩展

本页介绍如何使用 Lockra 扩展在 Chrome、Edge 和 Firefox 中填充密码和验证码：安装与配对、填充与保存，以及决定扩展可以做什么的设置。

<StatusTag status="available" /> 自 0.10.0 版起在 Windows、macOS 和 Linux 上提供。扩展从 Lockra 保存它的文件夹加载，见[安装扩展](#安装扩展)，那里也说明了各商店的情况。

扩展本身不保存任何密码。它向同一台电脑上的 Lockra 请求，两者之间的连接经过加密，并且只在 Lockra 运行且已解锁时才能请求；是否可以填充某个网页、填充哪个登录项，都由 Lockra 决定。扩展随 Lockra 一起锁定和解锁，从不要求输入主密码。

## 准备工作

- Windows、macOS 或 Linux 上的 Lockra 0.10.0 或更高版本，与浏览器在同一台电脑上运行（从 Lockra 的文件夹加载扩展、由 Lockra 更新扩展需要 0.11.1 或更高版本）。
- Chrome 或 Microsoft Edge 133 及以上，或 Firefox 140 及以上。Lockra 也会为 Chromium 和 Brave 完成设置，它们安装和 Chrome 相同的程序包。不支持以 Snap 或 Flatpak 形式安装的浏览器（[平台说明](/zh/reference/platforms#浏览器扩展)）。
- 保险库中已有登录项（[密码](/zh/passwords/)）。

## 安装扩展

| 浏览器                        | 来源                                | 状态                             |
| ----------------------------- | ----------------------------------- | -------------------------------- |
| Chrome、Edge、Brave、Chromium | Lockra 的扩展文件夹，以解压方式加载 | <StatusTag status="available" /> |
| Microsoft Edge                | Microsoft Edge 加载项               | <StatusTag status="building" />  |
| Firefox                       | Firefox 附加组件                    | <StatusTag status="building" />  |

扩展没有上架 Chrome 网上应用店。自 0.11.1 版起，Lockra 自带与自己同版本的扩展，放在它自己的一个文件夹里，Chrome、Edge 和 Brave 以解压方式加载这个文件夹：

1. 在 Lockra 中打开「设置 › 浏览器」，开启「浏览器集成」（[开启浏览器集成](#开启浏览器集成)）。随后「扩展文件夹」会显示这个文件夹，并提供「复制路径」和「打开文件夹」：

   | 系统    | 文件夹                                                   |
   | ------- | -------------------------------------------------------- |
   | Windows | `%LOCALAPPDATA%\Lockra\browser\extension`                |
   | macOS   | `~/Library/Application Support/Lockra/browser/extension` |
   | Linux   | `~/.local/share/Lockra/browser/extension`                |

2. 打开浏览器的扩展页面（`chrome://extensions`、`edge://extensions` 或 `brave://extensions`），开启「开发者模式」，并保持开启：关闭后，以解压方式加载的扩展在重新载入时会被浏览器停用。
3. 选择「加载已解压的扩展程序」，选中这个文件夹：可以在对话框中粘贴复制的路径。

扩展的卡片上显示的 ID 是 `flgfdomeabdfbebfjonaocddjcamgblk`，与 Edge 加载项将要发布的扩展相同；Lockra 不与其他 Chromium 扩展连接。以前从发布包加载过扩展的，同样加载 Lockra 的文件夹即可：ID 相同，它会替换原来的扩展，配对保留。

同一节的「下载扩展安装包」会打开与 Lockra 同版本的发布包 `lockra-extension_<版本>_chromium-unpacked.zip`：解压到一个会长期保留的文件夹，再加载这个文件夹（使用 Lockra 0.10 时只能这样安装）。这样装的扩展不会随 Lockra 更新：更新时用新版本的程序包替换文件夹中的文件，再点击扩展卡片上的重新加载按钮。发布页上另一个 Chromium 文件 `lockra-extension_<版本>_chromium-store.zip` 是提交给商店的程序包，以解压方式加载时 ID 不同，无法连接。移除扩展会清除配对，重新加载扩展后需要再配对一次。Edge 加载项上架后，Edge 也可以改从那里安装；两者 ID 相同，请先移除以解压方式加载的扩展。

Firefox 只安装经 Firefox 附加组件签名的扩展，所以 Firefox 版扩展要等商店页面上线后才能安装。

## 随 Lockra 更新

<StatusTag status="available" /> 自 0.11.1 版起提供。

Chrome、Edge 和 Brave 不会更新以解压方式加载的扩展，所以由 Lockra 来更新：Lockra 每次更新，启动时都会把新版扩展放进它的文件夹。扩展发现后，等它的弹窗、选项页和菜单都关闭，就自行重新载入，配对保留；已经打开的网页刷新后才会用上新版扩展。

扩展比 Lockra 旧时，弹窗会提示；如果扩展是以其他方式安装的，还会建议改为加载 Lockra 的文件夹。「设置 › 浏览器」会显示每个已配对扩展的版本，比 Lockra 旧的标为「可更新」。Firefox 不保留以解压方式加载的扩展，这一节不适用于 Firefox。

## 开启浏览器集成

1. 在 Lockra 中打开「设置 › 浏览器」，开启「浏览器集成」。Lockra 会为在这台电脑上找到的每个浏览器写入一个连接文件（native messaging 清单），扩展才能与它通信；在 Windows 上，当前用户的注册表中还会有一项指向每个文件。
2. 扩展只在 Lockra 运行时可用，因此 Lockra 会询问是否在关闭窗口后继续运行：选择「开启后台运行」即可开启（[后台运行](#后台运行)）。

随后，「浏览器」会列出每个浏览器及其状态：有已配对的扩展连接着时显示「已连接」，曾经配对过时显示「清单已写入」，从未配对过时显示「未安装扩展」。Lockra 无法得知扩展是否已安装，只知道它是否配对过。在开启集成之后才安装的浏览器会显示「写入」按钮：选择它即可为这个浏览器写入连接文件。

关闭「浏览器集成」会删除这些连接文件，并断开所有扩展。

## 与 Lockra 配对

1. 点击浏览器工具栏中的 Lockra 图标，选择「连接」。
2. 扩展和 Lockra 会各显示一个 6 位代码；Lockra 的窗口会来到前台，显示「Chrome 请求连接」（或你所用的浏览器）。请确认两边的代码相同。
3. 在 Lockra 中输入主密码批准；Lockra 可以用 Touch ID 或 Windows Hello 解锁时，也可以用它们批准。代码不一致时，请选择「拒绝」。

配对请求两分钟后过期，同时最多有 3 个请求在等待。每个浏览器以及它的每个用户配置文件分别配对。「设置 › 浏览器」中的「已配对的扩展」列出它们，以及各自的配对时间和最近使用时间；「取消配对」会立即断开该扩展，再次使用前需要重新配对。在扩展自己的设置页中也可以取消配对。

Lockra 锁定时，弹窗显示「在 Lockra 中解锁」，选择后 Lockra 的解锁页会来到前台。Lockra 没有运行时，弹窗显示「启动 Lockra」。

## 填充登录表单

Lockra 只提供与网页匹配程度最高的登录项（[网站与匹配方式](/zh/passwords/#网站与匹配方式)），收藏的登录项排在最前，其次是最近使用过的。

### 从弹窗填充

点击工具栏中的 Lockra 图标，或按 `Ctrl Shift Y`（macOS 上为 `⌘ Shift Y`），即可打开弹窗。弹窗列出当前网站的登录项；「填充」会把其中一个填入网页，⋯ 可以复制它的用户名、密码或验证码。「搜索全部登录项…」可以找到扩展能看到的任何登录项：与当前网页匹配的可以填充，其他的只能复制。

### 使用快捷键

在登录表单中点击输入框，然后按 `Ctrl Shift L`（macOS 上为 `⌘ Shift L`）：当前网站的第一个登录项会填入表单。10 秒内再按一次，则改为填充下一个账号。没有可以填充的登录项，或者 Lockra 已锁定或尚未配对时，弹窗会打开并说明原因。这两个快捷键可以在浏览器自己的快捷键设置中修改（Chrome 为 `chrome://extensions/shortcuts`，Edge 为 `edge://extensions/shortcuts`，Firefox 为附加组件管理器中的「管理扩展快捷键」）。

### 从输入框旁的菜单填充

获得[网站访问权限](#网站访问权限)后，点击登录输入框时会打开 Lockra 的菜单，列出当前网站的登录项：用方向键选择后按 Enter，或直接点击即可填充；按 Esc 关闭菜单。输入框末端的 Lockra 标志可以再次打开菜单。浏览器可能在输入框下方列出它保存的密码，这时 Lockra 的菜单改在输入框上方打开，上方放不下时仍在下方（[浏览器自带的密码功能](#浏览器自带的密码功能)）。浏览器的列表打开时，方向键和 Esc 先交给它：按 Esc 关闭它之后，方向键就会在 Lockra 的菜单中移动。

无论用哪种方式填充，都只会填入当前所在表单中可见的字段，以及登录项中指定了页面字段的自定义字段。只有在你开启了「填充后自动提交」时，填充后才会自动提交表单：

- 只要求用户名的一步不提交，留给你点「下一步」。
- 登录项没有关联验证码时，填入密码后提交。
- 登录项关联了验证码时，填入验证码后才提交：密码和验证码在同一页时，两个都填好再提交；验证码在下一页时，密码页留给你点「登录」，验证码页填好后提交。

提交时，Lockra 像你按 Enter 一样点击表单的提交按钮，会跳过「获取验证码」「取消」和第三方登录之类的按钮；网页尚未启用按钮时，最多等 1 秒，仍不可用就不提交。

### 分几页的登录

先输入用户名、下一页再输入密码的登录，只需在第一页填一次：你点「下一步」后，2 分钟内这个网站的下一页出现密码框时，Lockra 会自动填入同一个登录项的密码。这只发生一次，而且只在同一个标签页、同一个网站。保护级别为「填充前验证」的登录项，或者表单在其他网站的框架里时，不会自动接着填，需要你像平常一样再填一次。页面加载时的自动填充不会接着填下一页。

### 需要先确认的填充

- **保护级别为「填充前验证」的登录项**会在 Lockra 中等待你的确认：Lockra 的窗口来到前台，显示网站和登录项，输入主密码或通过 Touch ID、Windows Hello 验证后才会填充。无人回应的请求会在 60 秒后自动拒绝。
- **「填充前确认」**（见下文）会在菜单或快捷键填充之前，先在网页中询问「填充「…」？」，选择「填充」后才会填充。
- **HTTP 网页**：登录项保存的是 `https://` 网址时，网页会提示「这个页面没有加密（HTTP）」：在这样的网页中填入的密码，同一网络中的其他人可能看到。选择「仍然填充」才会填充。
- **其他网站框架中的表单**默认从不填充。设置为「先询问」时，Lockra 会显示框架所属的网站和顶层网页，选择「仍然填充」后才会填充。

## 下一页的验证码

登录项关联了验证码时，扩展会在填入密码之后填入验证码：填入同一个网页的验证码框；如果登录分为几步，还会在 5 分钟内填入同一网站之后页面的验证码框，包括网页不刷新、只换了内容的单页登录。开启了「填充后自动提交」时，填入验证码后会提交（见上文）。Lockra 能识别标记为一次性验证码的输入框、以验证码命名的输入框，以及每位数字一个格子的验证码框；不会把验证码填进图形验证码框，或者旁边有「获取验证码」按钮、写明短信或邮箱的验证码框。验证码还会放入剪贴板，并在「设置 › 安全 › 清空剪贴板」设定的时间后清空。「填入验证码」和「复制验证码」可以分别关闭这两项（[扩展可以做什么](#扩展可以做什么)）。下一个网页上的填充需要网站访问权限。

### 单独的验证码框

<StatusTag status="building" /> 下一个版本起，Lockra 还能识别以身份验证器命名、或只接受数字的验证码框，例如登录 Google 时从设备确认改用身份验证器后显示的那个，验证码同样会填进去。如果这个标签页 5 分钟内没有用 Lockra 填过登录项（前几步是手动输入的，或者已经超时），点一下验证码框就会弹出菜单，列出这个网站关联了验证码的登录项：选一个，就填入它的验证码。

## 保存与更新密码

获得网站访问权限后，扩展会留意你提交的表单：

- 提交的用户名和密码不在 Lockra 中时，网页右上角会显示「保存到 Lockra？」，其中的标题、用户名、密码和分组可以核对后再保存。「保存」会为这个网站添加登录项，「不保存」会放弃这次提交，「此网站不再提示」会把这个网站加入「不提示保存」。
- 已有的用户名配上新的密码时，会显示「更新 Lockra 中的密码？」。「更新」会修改这个登录项的密码，旧密码进入它的密码历史。
- 分两步的登录（先在一个页面输入用户名，再在下一个页面输入密码）会被合并处理：扩展在内存中保留用户名 5 分钟。
- 在注册表单或设置新密码的表单中，密码框旁的菜单会提供「使用生成的密码」；网页或 Lockra 知道该网站的密码规则时，按规则生成。「使用」会填好所有新密码框（包括确认密码框），并立即在 Lockra 中添加这个登录项。同一个表单的其他密码框提供的是同一个密码，在最后一次打开菜单后保留 5 分钟；「换一个」会生成新的密码。再次使用不会新建第二个登录项：第一次使用后换的新密码会改为更新那个登录项的密码。「复制密码」经 Lockra 放入剪贴板，并在「设置 › 安全 › 清空剪贴板」设定的时间后清空。

对于「不提示保存」名单上的网站，或已经保存过的登录信息，扩展不会提示。

## 网站访问权限

没有你所访问网站的访问权限时，扩展只在你使用它时才在网页中运行：只能使用弹窗和快捷键。在弹窗中选择「在网页中启用 Lockra」，或在扩展的设置页中选择「授予权限」，浏览器就会请你授予这项权限。获得权限后，扩展还会提供输入框旁的菜单、保存和更新提示、注册表单中生成的密码、下一个网页上的验证码，以及（在你开启时）页面加载时自动填充。

在浏览器自己的扩展设置中，或在扩展设置页中选择「收回权限」，即可收回这项权限。没有网站访问权限的已配对扩展，会在 Lockra 的「设置 › 浏览器」中注明。

## 浏览器自带的密码功能

浏览器也会保存密码，点击输入框时，它的密码列表（带钥匙图标）会出现在输入框下方，也就是 Lockra 菜单原本打开的位置。扩展的设置页（弹窗右上角的齿轮）在「浏览器自带的功能」中提供：

- **让 Lockra 接管浏览器的密码功能**：关闭浏览器的「提示保存密码」，只由 Lockra 提示保存和更新。第一次开启时，浏览器会请你授予「更改隐私相关设置」的权限；关闭这个开关会把浏览器原来的设置还给它，并一起收回这项权限。在 Firefox 中，开启后 Firefox 也不再填入和列出它保存的密码，这些密码仍留在它的密码管理中。
- 在 Chrome 和 Edge 中，浏览器已经保存的密码不受这个开关影响：在你删除之前，浏览器会继续填入它们，并在输入框下方列出。先在浏览器的密码设置中把它们导出为 CSV 文件，再导入 Lockra（见[导入与导出](/zh/passwords/import-export)），核对无误后，到浏览器里删除；「打开浏览器的密码管理」可以直接打开那里。在 Chrome 中一次删除全部数据时，通行密钥也会一并删除；开启了同步时，Google 账号中的密码也会删除。
- **同时关闭地址和付款方式的自动填充**（Chrome 和 Edge）：浏览器不再在表单中提示地址和银行卡。Lockra 不填写这两类内容，需要浏览器帮你填写时请保持关闭。
- **避开浏览器自己的密码列表**（默认开启）：Lockra 的菜单开在输入框上方，浏览器的列表在下方；上方放不下时，菜单仍在下方。在 Firefox 中，接管浏览器的密码功能后，Firefox 不再列出密码，菜单留在下方。浏览器里不再保存密码后，可以关闭这个开关，让菜单回到下方。
- **点击输入框时打开 Lockra 菜单**（默认开启）：关闭后，只在点击输入框末端的 Lockra 标志时打开。

浏览器的策略或其他密码管理器的扩展控制着这些设置时，设置页会说明开关未生效。Firefox 只允许扩展关闭保存密码这一项。

## 扩展可以做什么

「设置 › 浏览器 › 自动填充」决定这台电脑上所有已配对的扩展可以做什么：

| 设置                       | 默认     | 作用                                                                               |
| -------------------------- | -------- | ---------------------------------------------------------------------------------- |
| **填入验证码**             | 开       | 把登录项关联的验证码填进网页的验证码框                                             |
| **复制验证码**             | 开       | 同时把这个验证码放入剪贴板                                                         |
| **填充后自动提交**         | 关       | 填入密码后提交表单；关联了验证码的登录项在填入验证码后提交；只填用户名的一步不提交 |
| **填充前确认**             | 关       | 每次填充前先在网页中确认                                                           |
| **其他网站框架里的登录框** | 从不填充 | 「从不填充」，或在 Lockra 中「先询问」                                             |
| **页面加载时自动填充**     | 关       | 打开匹配的网页时不经点击就填入（见下文）                                           |

让扩展可以做更多事情的修改，需要输入主密码或通过 Touch ID、Windows Hello 验证：开启「填入验证码」「填充后自动提交」或「页面加载时自动填充」，关闭「填充前确认」，或选择「先询问」。这些设置保存在保险库中，只对这台设备有效。每个登录项还可以为自己单独设置「页面加载时填充」「填充后自动提交」和「填入验证码」（[保护级别](/zh/passwords/#保护级别)）。

### 匹配端口

<StatusTag status="building" /> 下一个版本起，「设置 › 浏览器 › 自动填充」新增「匹配端口」，默认关闭。开启后，只有端口也一致时才提供登录项，同一地址的不同端口各用各的登录项，例如 `http://192.168.1.10:5000` 上的 NAS 和 `http://192.168.1.10` 上的路由器。没写端口的网址只匹配协议的默认端口：`https://example.com` 的登录项不会出现在 `https://example.com:8443` 上。「主机」「开头匹配」和「精确」本来就比较端口，「正则」仍按表达式匹配。开启或关闭都不需要验证，因为它只会减少扩展拿到的登录项。

### 页面加载时自动填充

「页面加载时自动填充」会在匹配的网页打开时，不经点击就填入登录项。开启前，Lockra 会先说明它的风险：按默认的注册域匹配时，这个网站任何一个子域中的一段恶意脚本，都能在你不知情时读到填入的密码，开启这项设置后，它甚至不需要你的任何点击。开启后，只有同时满足以下条件时 Lockra 才会填充：

- 表单位于网页本身，而不是框架中；
- 网页使用 HTTPS，或与登录项保存时的协议一致；
- 恰好只有一个匹配程度最高的登录项；
- 登录项的保护级别为「直接填充」，且它自己没有关闭这项设置；
- 网站不在「禁止填充」名单上；
- 输入框可见。

即使开启，也从不填入验证码、从不自动提交。这项功能需要网站访问权限，并且只有选择「继续…」并输入主密码或通过 Touch ID、Windows Hello 验证后才会开启。

## 网站名单

「设置 › 浏览器」中的「网站名单」包含两个名单：「不提示保存」中的网站不会出现保存或更新提示，「禁止填充」中的网站不会填入任何内容。选择「添加网站…」即可添加；名单中的网站包括它的子域。名单保存在保险库中，并会同步到你的其他设备。

## 最近活动

「最近活动」列出扩展做过的事情和 Lockra 拒绝的请求：配对、填充、验证码、复制、保存和更新，以及时间、浏览器和网站。它只保存在内存中，最多 100 条，Lockra 锁定时清空；选择「清空」可以立即清空。

请求过于频繁的扩展会被暂停：1 分钟内取得超过 10 个密码或验证码、1 分钟内超过 120 次请求，或 10 分钟内取得超过 20 个网站的密码。暂停期间，这个扩展拿不到任何密码，「设置 › 浏览器」会显示它已暂停，并提供「恢复」：确认这些请求都是你自己的操作后再恢复。

## 后台运行

「设置 › 浏览器 › 关闭窗口后继续运行」会在你关闭窗口后让 Lockra 留在托盘中继续运行，扩展因此仍然可用。Lockra 运行时托盘图标始终存在（[托盘图标](/zh/guide/quick-start#托盘图标)）：点击图标会打开窗口，在 macOS 上点击程序坞中的 Lockra 图标也会打开窗口；它的菜单提供「打开 Lockra」「快捷搜索」（[全局快捷搜索](/zh/passwords/#全局快捷搜索)）「锁定」「设置…」「检查更新…」和「退出 Lockra」。需要你确认的配对或填充会自动让窗口出现。关闭这项设置时，关闭窗口即退出 Lockra，与以往相同。

Lockra 在后台运行时，保险库保持解锁状态，直到在「设置 › 安全」设定的无操作时间后自动锁定，或你从托盘中锁定。部分 Linux 桌面不显示托盘图标，例如未安装 AppIndicator 扩展的 GNOME：在这些桌面上，没有任何迹象表明 Lockra 仍在运行，再次启动 Lockra 即可让窗口重新出现。

开启这项设置时，扩展中的「启动 Lockra」会在托盘中启动 Lockra；未开启时，Lockra 启动后会显示窗口。

## 扩展能看到和看不到什么

- **没有保险库。** 扩展不保存任何登录项。只有在你填充或复制时，登录项的密码才会交给扩展；用于填充时，只交出与当前网页匹配的登录项的密码。保护级别为「不交给扩展」的登录项，扩展完全看不到，搜索中也没有。
- **浏览器中保存的内容。** 扩展自己的密钥、配对信息，以及点击输入框时是否打开菜单，保存在你的浏览器配置文件中；使用期间，它最近一次列出的当前网站的登录项（标题和用户名，不含密码）保存在浏览器的内存中，Lockra 锁定时清除。
- **不联网。** 扩展只经浏览器的 native messaging 与同一台电脑上的 Lockra 通信，通信内容端到端加密；它不向其他任何地方发送内容，也不收集任何数据。
- **网页无法冒充。** Lockra 检查的是浏览器报告的网页地址和表单所在框架的地址，从不采信网页对自己的描述；网页也无法替你点击 Lockra 的菜单：只有菜单已经显示至少 300 毫秒、没有被遮挡也没有移动时，点击才有效。
- **无权更改规则。** 扩展无法解锁 Lockra，也无法让自己做更多事情：只有 Lockra 的「设置 › 浏览器」可以。

Lockra 无法防范的情况，见 [Lockra 如何保护你的账号](/zh/security/#lockra-无法防范的情况)。
